# PassGuard

A locally-hosted password-manager vault inspired by Delinea Secret Server.  
All credentials are stored in a SQLite database on your own machine and encrypted with **Fernet (AES-128-CBC)**, with the encryption key derived per-session from your master password using **PBKDF2-SHA256** (480 000 iterations). The master password itself is never stored — only its **bcrypt** hash is persisted.

---

## Features

| Area | Details |
|---|---|
| **Vault lock/unlock** | Single master password gates all access; clearing the in-memory key locks the vault instantly |
| **Credential CRUD** | Store site name, URL, username, password, and free-text notes |
| **Password generator** | Built-in HTML frontend for generating strong passwords |
| **REST API** | FastAPI backend with auto-generated Swagger docs at `/docs` |
| **Local-only storage** | SQLite — no cloud sync, no third-party calls |
| **One-click launch** | PowerShell script starts the server and opens the UI in your browser |

## Quick Start (Windows)

### 1. Install dependencies

Open a terminal in the project root and run:

```powershell
python -m pip install -r backend\requirements.txt
```

### 2. Launch the app

```powershell
.\launch.ps1
```

The script will:
1. Kill any previous process listening on port 8000.
2. Start the FastAPI server in the background.
3. Poll `http://127.0.0.1:8000/vault/status` until it is ready.
4. Open `password-generator.html` in your default browser.

Press **Ctrl+C** in the PowerShell window to shut the server down.

--- 

##(Linux / macOS / any platform)

```bash
pip install -r backend/requirements.txt
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Then open `password-generator.html` directly in your browser.

## API Overview

Interactive docs are available at **http://127.0.0.1:8000/docs** once the server is running.

### Vault

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/vault/status` | Check whether the vault is set up and/or unlocked |
| `POST` | `/vault/setup` | First-time master password creation |
| `POST` | `/vault/unlock` | Unlock the vault (loads encryption key into memory) |
| `POST` | `/vault/lock` | Lock the vault (wipes the in-memory key) |

### Credentials

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/credentials` | Save a new credential |
| `GET` | `/credentials` | List all credentials (passwords hidden) |
| `GET` | `/credentials/{id}` | Retrieve a credential with decrypted password |
| `PUT` | `/credentials/{id}` | Update a credential |
| `DELETE` | `/credentials/{id}` | Delete a credential |

### Generated Passwords

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/passwords` | Save a generated password |
| `GET` | `/passwords` | List saved passwords (values hidden) |
| `GET` | `/passwords/{id}` | Retrieve a saved password by ID |
| `DELETE` | `/passwords/{id}` | Delete a saved password |

## Security Design

- **Master password** — hashed with `bcrypt` before being stored; never written in plaintext.  
- **Encryption key** — derived at unlock time via `PBKDF2-SHA256` (480 000 iterations + random 16-byte salt) and held only in memory. It is wiped when the vault is locked or the server stops.  
- **Credential passwords** — encrypted with `Fernet` (AES-128-CBC + HMAC-SHA256) using the in-memory key before being written to SQLite.  
- **Vault is locked by default** — all credential endpoints return `403 Forbidden` until `POST /vault/unlock` is called.
